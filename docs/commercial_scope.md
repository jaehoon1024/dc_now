# 상용 데이터센터 수집 범위

## 기본 원칙

플랫폼의 시장 공급 집계 대상은 제3자 고객에게 상면, 전력, IT 용량 또는 데이터센터 시설을 계약 형태로 제공하는 국내 상용 데이터센터다.

다음 계약·운영 모델을 포함한다.

- 코로케이션
- 도매형 코로케이션
- 마스터리스
- 임차 운영
- Build-to-Suit
- 제3자 대상 매니지드 데이터센터 서비스
- 위 모델을 함께 제공하는 복합 모델

## 시장 공급 집계 조건

센터는 아래 조건을 모두 충족할 때만 시장 KPI, 지도 기본 화면, 지역·사업자 공급 분석에 포함한다.

1. `commercial_scope_status = IN_SCOPE`
2. `commercial_review_status = CONFIRMED`
3. 사업자 공식 센터 목록, 공식 서비스 자료, 공시 또는 동등한 근거에서 제3자 대상 상용 공급을 확인

상용성이 확인되지 않은 개발 후보는 `REVIEW_REQUIRED`로 유지하고 시장 공급량에 합산하지 않는다.

## 제외 범위

- 기업·금융사·방송사·게임사 등의 자가사용 전산센터
- 중앙정부·지자체·공공기관의 행정 전산센터
- 대학·연구기관의 전용 HPC 시설
- 물리 시설을 특정할 수 없는 클라우드 리전과 가용영역
- 통신국사, 일반 사옥, 연구소 등 제3자 데이터센터 공급이 확인되지 않은 시설

제외 대상은 삭제하지 않고 `OUT_OF_SCOPE`로 보존하여 판정 근거와 변경 이력을 추적한다.

## 상용 모델 코드

| 코드 | 의미 |
|---|---|
| `COLOCATION` | 코로케이션 |
| `WHOLESALE` | 도매형 코로케이션 |
| `MASTER_LEASE` | 마스터리스 |
| `LEASED` | 임차 운영 |
| `BUILD_TO_SUIT` | 특정 고객용 맞춤 개발 |
| `MANAGED_SERVICE` | 제3자 대상 매니지드 서비스 |
| `MULTI_MODEL` | 두 가지 이상 모델 |
| `UNKNOWN` | 모델 확인 필요 |

## 검토 절차

1. 후보 센터를 `REVIEW_REQUIRED / NEEDS_EVIDENCE`로 등록한다.
2. 공식 자료에서 센터명, 위치, 사업자 역할, 제3자 공급 여부를 확인한다.
3. 계약 모델과 근거 URL을 기록한다.
4. 확인되면 `IN_SCOPE / CONFIRMED`, 자가사용 등으로 판정되면 `OUT_OF_SCOPE / CONFIRMED`로 변경한다.
5. 상용 확정 이후 운영 단계, MW, RFS와 시설 정보를 공급 분석에 반영한다.
