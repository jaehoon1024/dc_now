# 추정값과 담당자 키인 — 2026-10-13

## 적용 결과

상용 관리 대상66곳 중 IT 용량을 계산할 수 있는 센터는 원문 검증값만 적용하면7곳이며, 발표·추정값을 포함하면64곳이다. 운영51곳과 개발13곳에 계산 가능한 값이 있다. 나머지2곳은 운영/개발 단계부터 확인하거나 담당자가 입력해야 한다. 초기 작업값73건은 추정71건과 발표값2건이다. 기업 전용·클라우드 자체센터 및 미검증 후보의 범주는 별도 필터로 유지한다.

기본 집계는 **발표·추정·담당자 입력 포함**이다. **원문 검증값만**으로 바꾸면 원래 확인한 제원과 일정을 조회한다. 화면·CSV에 값의 상태를 표시한다. 원문 검증 데이터는 작업값에 의해 수정되지 않는다.

## 초기 산정 방법

1. 확인한 수전용량이 있는 센터: 수전MW ÷ 가정 환산계수1.5로 설계 IT 규모를 추정한다. 계수1.8~1.3에 해당하는 범위를 함께 기록한다. 실제 PUE·피크부하·가용용량을 확정한 값이 아니다.
2. 용량 경계가 미공개인 발표 규모: 수전 규모라는 해석 가정을 붙여 변환한다. 군산1단계60MW→IT40MW, SKB 가산46MW→IT약30.667MW, 울산 전체103MW→IT약68.667MW가 이에 해당한다.
3. 파주1동: KB증권 리서치가 제시한 IT약40MW를 발표값으로 사용한다. 캠퍼스200MW 수전과1동40MW IT를 중복 합산하지 않는다.
4. 울산1차: SKT 뉴스룸의 외부 기고41MW를 수전으로 해석해 IT약27.333MW, 최초 가동2027년11월을 발표·추정 일정으로 사용한다. 사업자 공식 IT제원으로 확정하지 않는다.
5. 남구로: 공식345랙 × 가정6kW/랙 =IT2.07MW, 4~10kW/랙 기준 범위1.38~3.45MW를 사용한다.
6. 시설별 숫자가 없는 센터: 원장 공개 운영 IT표본7곳의 중앙값26MW를 초기 시나리오로 사용하고, 표본이 대표성을 보장하지 않으므로0.25~2배(6.5~52MW)의 넓은 범위를 둔다. 개별 시설의 규모에 관한 관측값이 아니다. 담당자가 우선 수정할 항목이다.
7. 미공개 공급 일정: 건설+2년, 부지·인허가·전력확보+3년, 초기계획+4년, 가동준비+1년을2026년 기준으로 고정 입력한다. 준공 예정 월이 있으면 가동 준비6개월을 더한 분기를 초기 가정으로 사용한다. 조회할 때마다 미래로 밀리지 않는다.

기존 공개 발표 수치는 센터 전체·단일 프로젝트 범위가 확인되는 경우에만 표본 추정보다 우선 사용한다. 여러 프로젝트나 Phase의 발표를 임의로 캠퍼스 전체에 적용하지 않는다. 미확인 사업자는 새 센터로 중복 생성하지 않는다.

추정 범위 합계는 입력 가정의 낮은 값·높은 값을 합산한 시나리오 범위다. 통계적 신뢰구간이나 시장 전체의 확정 공급량을 의미하지 않는다. Phase별 공급 전망은 개별 Phase의 용량·일정을 사용하며 캠퍼스 전체를 모든 Phase에 반복하지 않는다.

## 직접 수정

센터 상세 → **추정·키인 수정**에서 센터 전체, 프로젝트 또는 Phase를 선택한다. IT Load, 수전용량, 운영 개시 예정, 준공 예정, 상태, 주소, 운영사, PUE를 입력할 수 있다.

- 값 상태: 발표값 / 추정 / 담당자 입력 / 담당자 확정
- 숫자 범위: 선택 입력, 낮은 값 ≤ 입력값 ≤ 높은 값
- 일정: 연도·분기·월·일 중 실제 알고 있는 정밀도로 입력
- 산정 근거·수정 사유: 필수
- 근거 URL: 선택
- 공개 표시: 선택. 비공개 작업값은 공개 스냅샷에서 제외

담당자 입력·확정은 작업 집계에서 기존 값을 수정할 수 있다. 새 원문 검증값이 수집되면 자동 추정치보다 우선한다. 담당자 확정은 담당자 판단의 기록이며 원문 검증 데이터로 자동 승격하지 않는다. 값 사용 해제로 작업값을 철회할 수 있다.

### 공개 GitHub Pages

키인한 값은 **내 브라우저 수정안**으로 저장한다. 수치·목록·공급 전망에 즉시 적용되고 새로고침 후에도 유지된다. N100 원장을 공유 수정한 것으로 표시하지 않는다.

**전체 수정안 다운로드**로 JSON을 저장하고 담당자 화면에서 가져오면 공유 원장에 반영할 수 있다. 브라우저 저장 실패 시에는 파일 다운로드 안내를 표시한다. 인증정보를 브라우저 저장소에 기록하지 않는다.

### N100 담당자 화면

[담당자 화면](http://localhost:8766/)에서 기존 인증 후 같은 탭으로 이동한다. **원장에 저장**은 DB에 즉시 반영한다. **수정안 가져오기**는 파일의 여러 변경을 한 번에 저장한다. 한 항목이라도 실패하면 전부 롤백한다.

**공개 게시 요청**은 기존 dc-dashboard-publish.service를 실행한다. 일반 수집·게시 타이머도 저장값을 반영한다. 비공개 센터·프로젝트·Phase에 연결한 작업값은 공개 승인 조건을 충족하기 전 공개 스냅샷에 포함하지 않는다.

## 저장 및 검증

0033_planning_values 테이블에서 원장 대상, 값, 범위, 산정 근거, URL, 공개 여부, 활성 여부, 수정자·시각·버전을 관리한다. 모든 수정은 audit_log에 이전값과 새값을 남긴다. 버전이 달라진 동시 수정은409로 거절하며 덮어쓰지 않는다. API는 기존 Bearer 인증을 사용하며 게시 요청의 서비스명은 고정돼 있다.

초기 추정 스크립트(src29_seed_planning.py)는 기존 입력·철회값을 보존한다. --refine-bootstrap은 초기 표본 가정을 공개 시설 수치로 개선할 때에만 사용하며 담당자 입력값을 수정하지 않는다. 수집기가 운영·개발 원문을 갱신해도 담당자 작업값과 그 이력은 유지된다.

검증: 실제 DB 롤백 테스트를 포함한100개 테스트, 집계 계산 테스트, 데스크톱·390px 브라우저 테스트, 공개 수정안 저장·재조회·다운로드, 담당자 저장·가져오기·게시 요청 확인. 실제 서비스에서 작업값73건 조회 성공. 저장·가져오기·게시 버튼의 브라우저 검사는 mock 쓰기로 수행하며 운영 DB를 임의 수정하지 않는다.
