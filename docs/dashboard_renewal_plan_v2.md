# DC NOW 전체 리뉴얼 기획안 V2

## 1. 제품 재정의

DC NOW는 데이터센터 목록을 보여주는 대시보드가 아니라, 국내 데이터센터 공급과 사업기회를 조사하고 확정하는 **시장 운영 시스템**으로 설계한다.

사용자는 다음 업무를 한 흐름에서 처리해야 한다.

1. 시장 전체의 운영·개발 공급량과 변화를 파악한다.
2. 특정 지역, 사업자, RFS 시점의 공급을 분석한다.
3. 개별 센터의 전력·용량·시설·사업자·고객 정보를 조사한다.
4. 기사·공시·사업자 자료에서 들어온 후보 정보를 검토한다.
5. 승인된 변경을 지도, 센터 원장, 공급 전망에 반영한다.

## 2. 핵심 설계 원칙

### 2.1 업무 화면으로 설계

- 첫 화면에서 홍보 문구와 큰 장식 영역을 제거한다.
- 화면 상단부터 경보, 시장 KPI, 지도, 공급 전망, 검토 업무를 보여준다.
- 한 화면에서 비교와 판단이 가능하도록 정보 밀도를 높인다.

### 2.2 사실과 추정을 시각적으로 분리

| 상태 | 의미 | 화면 표현 |
|---|---|---|
| 확정 | 공식자료 또는 복수 근거로 확인 | 진한 글자, 녹색 확인 표시 |
| 추정 | 기사·업계 자료를 바탕으로 산출 | 점선, 파란색 `추정` 태그 |
| 검증 중 | 수집됐으나 센터 연결 또는 값 검토 필요 | 주황색 `검토` 태그 |
| 오래됨 | 마지막 확인 후 90일 이상 경과 | 회색 또는 붉은 날짜 표시 |
| 미확인 | 근거가 없는 값 | 숫자 0 대신 `—` 표시 |

### 2.3 시설 범주를 처음부터 분리

- 상용 공급: 코로케이션, 도매형, 마스터리스, 임차 운영, BTS
- 클라우드·IT 자체 사용: CSP 및 IT 기업 자체 센터
- 기업 전용: 금융, 제조, 통신 등 기업 업무용 센터
- 후보 프로젝트: 상용성 또는 개발 여부를 검토 중인 시설

상용 공급량 KPI에는 상용 확정 센터만 포함한다. 자체 사용 센터는 국내 디지털 인프라 분석에서 별도로 제공한다.

│           ├────────────────────────────────────────────────────────┤

### 전역 필터

- 시설 범주

필터는 화면을 이동해도 유지한다. 활성 필터와 집계 기준은 항상 표시한다.

## 5. 화면 1 — 시장 관제

### 목적

경영진과 시장조사 담당자가 30초 안에 시장 규모, 향후 공급, 주요 변화, 데이터 위험을 판단한다.

### 화면 배치

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 시장 관제                          기준: 2026.10.05  [필터 3개 적용]│
├──────────┬──────────┬──────────┬──────────┬──────────┬─────────────┤
│ 상용센터 │ 운영 MW  │ 건설 MW  │ 계획 MW  │ 3년 공급 │ Available  │
│  50개    │  00 MW   │  00 MW   │  00 MW   │  00 MW   │    — MW    │
├──────────────────────────────────────────┬──────────────────────────┤
│ 전국 공급 지도                           │ 오늘의 주요 변화         │
│ ● 운영  ● 건설  ○ 계획                  │ + 신규 프로젝트 3건      │
│ Bubble = IT Load                         │ ! RFS 변경 2건            │
│                                          │ ! 검토 지연 17건          │
├──────────────────────┬───────────────────┼──────────────────────────┤
│ 연도별 신규 공급 MW  │ 지역별 공급/수요  │ 운영 업무                │
│ 2027 2028 2029 2030  │ 수도권 / 충청 /…  │ 근거 검토 87             │
│                       │                   │ 좌표 확인 14              │
├──────────────────────┴───────────────────┴──────────────────────────┤
│ 사업자별 공급 순위 · GPU/DLC Ready · 데이터 최신성                 │
└─────────────────────────────────────────────────────────────────────┘
```

### 핵심 개선

- 센터 수보다 MW를 우선한다.
- 운영, 건설, 계획 공급량을 같은 단위로 비교한다.
- 최근 변경과 검토 업무를 우측에 고정한다.
- KPI마다 `확인 센터 수 / 전체 센터 수`를 함께 표시한다.
- 값을 확보하지 못했으면 0으로 보이지 않게 한다.

## 6. 화면 2 — 전국 지도

### 목적

입지, 지역 경쟁, 개발 집중, 전력 규모를 공간적으로 판단한다.

### 3단 구조

```text
┌ 필터·검색 320px ┬──────── Google Map ────────┬ 센터 상세 380px ┐
│ 검색            │ 운영: 초록                │ 센터명           │
│ 시설 범주       │ 건설: 주황                │ 상태 / 신뢰도    │
│ 운영 단계       │ 계획: 파랑 테두리         │ 사업자 관계      │
│ RFS             │ 원 크기: IT Load          │ 수전 / IT Load   │
│ IT Load         │ 클러스터: 지역 단위       │ RFS / GPU / DLC  │
│ 사업자          │                           │ 근거 보기        │
│ 데이터 품질     │                           │ 상세 화면 열기   │
└─────────────────┴───────────────────────────┴──────────────────┘
```

### 지도 동작

- 최초 진입 시 모든 상용 확정 센터를 표시한다.
- 좌표가 확인되지 않은 센터는 지도에서 숨기지 않고 좌측에 `좌표 미확인` 목록으로 제공한다.
- 같은 주소 또는 같은 캠퍼스의 Phase는 하나의 캠퍼스 마커로 묶는다.
- 운영과 개발을 동일한 색으로 표시하지 않는다.
- 주소 검색 결과를 확정 좌표처럼 사용하지 않는다.
- 지도 아래에 현재 화면 범위의 센터 수와 MW 집계를 표시한다.

## 7. 화면 3 — 센터 원장

### 목적

센터를 검색, 정렬, 비교하고 데이터 보완 업무로 연결한다.

### 테이블 기본 열

1. 센터명 / 캠퍼스
2. 시설 범주
3. 운영 단계
4. 지역
5. Owner
6. Operator
7. 수전용량
8. IT Load
9. Available Capacity
10. RFS
11. GPU / DLC
12. 신뢰도
13. 마지막 확인일

### 동작

- 열 표시와 순서를 사용자가 저장할 수 있게 한다.
- 2~5개 센터 선택 시 하단 비교 패널을 연다.
- 미확인 값만 필터링할 수 있게 한다.
- 행을 누르면 우측 미리보기를 열고, 전체 상세 화면으로 이동할 수 있게 한다.
- 엑셀 내보내기는 현재 필터와 표시 열을 따른다.

## 8. 화면 4 — 센터 360 상세

### 상단 고정 요약

```text
센터명 / 상태 / 시설 범주 / 신뢰도 / 마지막 확인일
Owner · Developer · Operator
[수전 MW] [IT Load MW] [Available MW] [RFS] [GPU] [DLC]
```

### 탭 구성

| 탭 | 핵심 내용 |
|---|---|
| Overview | 위치, 상태, 핵심 KPI, 최근 변화 |
| Phase | Phase별 IT Load, RFS, 공정상태 |
| Power | 계약전력, 수전용량, 변전소, 확보 상태 |
| Facility | PUE, Tier, UPS, 발전기, 냉각, Rack Density |
| Companies | Owner, Developer, Operator, Investor, 시공사 |
| Customer | Tenant, 수요, LOI, 계약, 입주시점 |
| Schedule | 인허가, 착공, 준공, RFS 일정 |
| Sources | 필드별 근거, 신뢰도, 확인일 |
| History | 이전 값, 현재 값, 변경자, 승인자 |

각 값 옆에 근거 아이콘을 배치한다. 사용자가 아이콘을 누르면 그 값을 뒷받침하는 기사, 공시, 공식자료를 바로 확인한다.

## 9. 화면 5 — 공급 전망

### 분석 단위

- 전국 / 지역 / 사업자 / 센터 / Phase
- 연도 / 분기
- IT Load / 수전용량 / 발표용량
- 확정 / 추정 / 검토 중

### 주요 시각화

1. 분기별 누적 공급 곡선
2. 신규 공급 MW 막대그래프
3. 지역별 공급 Heatmap
4. 사업자별 Phase Gantt
5. RFS 확정도 분포

그래프의 각 값은 해당 센터와 Phase 목록으로 드릴다운한다. 발표용량과 IT Load를 한 합계로 섞지 않는다.

## 10. 화면 6 — 플레이어 분석

### 대상

### 사업자 카드

- 관계 역할

- 개발 센터 수와 MW
- 지역 분포
- 향후 RFS

## 11. 화면 7 — 시장 이벤트

수집된 문서를 뉴스 목록으로만 보여주지 않고 시장 이벤트로 구조화한다.

### 이벤트 유형

- 토지 매입
- 전력 확보
- 인허가
- 착공
- 준공 / RFS
- 증설
- 고객 계약 / LOI
- 투자 / 매각
- 사업 지연 / 취소

### 화면 구성

- 좌측: 기간, 이벤트 유형, 센터, 사업자 필터
- 중앙: 시간순 이벤트 피드
- 우측: 연결 센터, 추출 값, 기존 값과 차이, 근거 문서

## 12. 화면 8 — 근거 검토

### 목적

자동 수집 결과를 사람이 빠르게 확정할 수 있게 한다.

```text
┌ 검토 큐 ─────────────┬ 후보 내용 ─────────────┬ 기존 원장 ───────────┐
│ RFS 변경 12          │ 기사 제목 / 원문       │ 현재 RFS: 2029 Q2    │
│ 용량 변경 8          │ 추출: 40MW, 2030 Q1    │ 현재 IT Load: 20MW   │
│ 신규 센터 17         │ 연결 후보 센터 3개     │ 근거 2건              │
│ 좌표 확인 14         │ 신뢰도 / 출처 등급     │ 변경 이력             │
├──────────────────────┴────────────────────────┴─────────────────────┤
│ [승인] [수정 후 승인] [보류] [중복] [범위 제외]                    │
└─────────────────────────────────────────────────────────────────────┘
```

승인 시 변경 값, 근거, 검토자, 승인일을 함께 저장한다. 일괄 승인은 동일 출처와 동일 변경 유형에만 허용한다.

## 13. 화면 9 — 데이터 품질 및 수집 운영

### 데이터 품질

- 필드별 확보율
- 90일 / 180일 이상 미확인 센터
- 좌표와 주소 불일치
- 운영 상태와 RFS 충돌
- 센터·사업자 중복 후보
- 근거 없는 공개 값

### 수집 운영

- 소스별 마지막 실행일
- 신규 / 중복 / 실패 / 제외 문서 수
- 수집 지연과 오류
- 센터 연결 성공률
- 자동 추출 성공률

관리자는 오류 메시지 원문보다 `어떤 소스가 언제부터 멈췄고 어떤 데이터가 영향을 받는지` 먼저 확인한다.

## 14. 비주얼 디자인 방향

### 스타일

- 금융·인프라 운용 시스템에 가까운 고밀도 데스크톱 UI
- 기본 배경은 밝은 회색, 분석 카드와 표는 흰색
- 좌측 메뉴는 짙은 남색
- 장식용 그라데이션과 대형 홍보 문구는 사용하지 않는다.

### 색상 의미

| 색상 | 사용 의미 |
|---|---|
| 남색 | 기본 정보와 탐색 |
| 녹색 | 운영, 확정, 정상 |
| 주황색 | 개발, 검토, 주의 |
| 파란색 | 계획, 추정 |
| 빨간색 | 실패, 지연, 충돌 |
| 회색 | 미확인, 비활성 |

### 숫자 표현

- `1,240 MW`처럼 값과 단위를 붙여 읽는다.
- 수치 아래에 `확인 18/50개`를 표시한다.
- 미확인 수치를 합산하지 않는다.
- 추정 합계는 `약 420 MW`처럼 구분한다.

## 15. 반응형 정책

- 핵심 사용 환경은 1440px 이상 데스크톱이다.
- 태블릿에서는 우측 상세 패널을 전체 화면 Drawer로 전환한다.
- 모바일은 시장 KPI, 주요 경보, 센터 검색과 상세 조회에 집중한다.
- 복잡한 비교표와 근거 승인 업무는 데스크톱 사용을 안내한다.

## 16. 구현 우선순위

### 1차 — 업무 기반 골격

- 새 좌측 메뉴와 전역 필터
- 시장 관제
- 전국 지도 3단 구조
- 센터 원장
- 센터 360 상세
- 상태·신뢰도 표현 통일

### 2차 — 분석 강화

- Phase 기반 공급 전망
- 플레이어 Portfolio
