# DC NOW 화면 설계 개편안

## 목표

센터 목록을 보여주는 화면에서 국내 데이터센터의 공급, 인프라 준비도, 사업기회와 데이터 신뢰도를 한 번에 판단하는 운영 화면으로 개편한다.

## 정보 구조

| 메뉴 | 사용자가 답을 얻어야 하는 질문 |
|---|---|
| 시장 관제 | 현재 운영·개발 공급 규모와 데이터 신뢰도는 어떤가? |
| 입지 지도 | 센터는 어디에 있고 지역별 경쟁과 전력 집중도는 어떤가? |
| 센터 원장 | 센터별 상태·용량·사업자·근거를 어떻게 비교하는가? |
| 공급 전망 | Phase와 RFS를 기준으로 언제 몇 MW가 공급되는가? |
| 플레이어 | Owner·Developer·Operator·Investor별 포트폴리오는 어떤가? |
| 수요 매칭 | 고객의 지역·시점·용량·GPU/DLC 조건에 맞는 후보는 어디인가? |
| 시장 이벤트 | 착공·전력·인허가·계약·투자 변화가 어느 센터에 연결되는가? |
| 데이터 관제 | 좌표·주소·용량·RFS·근거 중 무엇을 우선 보완해야 하는가? |

## 첫 화면 우선순위

1. 상용 확정, 클라우드·IT 자체 사용, 기업 전용 추적, 근거 보완 대상을 분리한다.
2. 운영·개발·혼합 센터 수와 운영 IT Load, 수전용량, 개발 IT Load, RFS 확보 현황을 KPI로 제공한다.
3. 전국 지도와 운영·개발 목록을 같은 화면에서 연결한다.
4. 지역별 공급, 연도별 RFS, 사업자 포트폴리오를 의사결정 차트로 배치한다.
5. 데이터 품질 점수와 누락 필드를 항상 노출하여 수치의 사용 가능 범위를 알린다.

## 시각 체계

- 짙은 남색 사이드바와 명령형 헤더로 시장 관제 도구의 성격을 강조한다.
- 청록색은 운영·정상, 주황색은 개발·검토, 붉은색은 오류·지연을 뜻한다.
- 큰 숫자와 단위를 분리하고, 각 수치 아래에 확보 건수 또는 산출 기준을 표시한다.
- 지도는 넓게 유지하고 상세 분석은 표, 차트, 오른쪽 패널로 이어지게 한다.
- 모바일에서는 메뉴, KPI, 지도, 표 순으로 한 열에 배치한다.

## 데이터 원칙

- 상용 데이터센터와 자체 사용 센터를 합산하지 않는다.
- 운영 중, 개발 중, 운영·개발 혼합 상태를 구분한다.
- 확인되지 않은 용량을 0으로 계산하지 않고 `미확인`으로 표시한다.
- 모든 핵심 정보는 근거 문서, 확인일, 신뢰도와 연결한다.
- 주소와 좌표는 별도 품질 항목으로 관리하여 지도 오표시를 방지한다.

## 다음 구현 단계

1. 현재 공개 데이터로 시장 관제, 지도, 센터 원장, 공급 전망을 완성한다.
2. Phase·Power·Cooling·Company Relationship 상세 모델을 API와 연결한다.
3. 고객 수요와 Available Capacity의 조건 매칭을 구현한다.
4. 변경 감지와 검토 승인 이력을 시장 이벤트 및 데이터 관제 화면에 연결한다.
