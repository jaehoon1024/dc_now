# NamePF 데이터센터 대시보드 수집 가능성 점검

점검일: 2026-10-13 · 참고 화면: https://dc.namepf.com/

## 결과

| 항목 | 확인 결과 |
|---|---|
| 공개 화면 | 일반 Chrome에서 조회 성공 |
| 공개 데이터 | `/data/dash.json`, `/data/geo.json` 확인. dash.json은 서버 HTTP 요청도 200 |
| 자료 기준 | 데이터 빌드 `2026-10-13 10:30`, 인허가 기준 `2026-10-12` |
| 수집 후보 | 인허가 138행, 대지 식별자 121종. 센터 수로 직접 환산하지 않음 |
| 좌표 | 시군구 대표점 3행, 동 대표점 101행, 리 대표점 34행. 정확한 센터 좌표로 확정하지 않음 |
| 용량 후보 | 분류 미확인 발표 MW 30항목, 수전 32항목, IT 27항목. 서로 다른 필드 수이며 센터 수가 아님 |
| 품질 점검 | DC 용도 면적이 총 연면적보다 큰 행 54건. 원대장·층별 용도 집계 기준 확인 필요 |
| robots | 200 응답이지만 HTML 대시보드 반환. 유효한 robots 규칙 미확인 |
| 재사용 | 공개 사실값·출처를 내부 후보로 정리. 전체 재배포 라이선스는 별도 확인 필요 |
| 후속 반영 | 공개 인허가 참고 원장·지역 전력 지표에 연결. SQL 원장 승인 상태와 별도로 관리 |

## 검토용 파일

- `output/source-audit/namepf-all-candidates.json`: 사실값·날짜·출처·해석 경고를 정규화한 138개 후보.
- `output/source-audit/namepf-candidates.json`: 최초 5개 샘플.
- 스킬: 사용자 스킬 디렉터리의 `dc-market-intelligence`.

후보는 외부 허가 ID와 대지 힌트를 보존한다. 사용승인일은 RFS로 변환하지 않고, 변전소 여유는 센터 확보 전력과 별도 정보로 남긴다. 기사 본문이나 지도 도형은 복제하지 않았다. 사이트가 제공하는 원본 지도 JSON은 일반 GeoJSON이 아니라 화면 투영 좌표·SVG 경로 자료였다.

## 후속 연결

1. 후보의 주소·대지·건물명과 DC NOW 캠퍼스/Phase를 대조한다.
2. 신축·증축·대수선·변경 허가를 분리하고, 같은 대지의 여러 허가를 중복 센터로 생성하지 않는다.
3. [건축HUB 원출처](https://www.data.go.kr/data/15136267/openapi.do)와 사업자 자료로 단계·용량·주소를 검증한다. 공식 인허가 API는 활용신청·인증이 필요하며 현재 안내의 갱신 주기는 월간이다.
4. 추정 및 발표 수치를 작업값으로 쓸 때 기준·범위·산정 방법을 남긴다.
5. 사용자 요청 범위에 맞춰 센터 연결, 필드 반영, 정기 수집과 공개 게시를 각각 진행한다.

## 스킬 검증

형식 검증 통과. 실제 샘플과 전체 인허가 JSON을 정규화해 용량 기준, 미확인/0 구분, 사용승인/RFS 구분, 대표점 표시, 면적 경고, 중복 허가 ID 탐지, URL에 포함된 인증정보 차단을 확인했다. 도구는 네트워크·DB 변경·게시를 실행하지 않는다.

## 후속 개발

사용자의 대시보드 개발·데이터 업데이트 요청에 따라 `src30_collect_permit_intelligence.py`와 `permit_intelligence.py`를 추가했다. 원장 주소 일치 20건은 17센터에 연결하고, 이름 힌트 5건·복수 원장 10건·미연결 103건을 별도로 표시한다. 정기 게시 과정에서 갱신하며, 실패 시 마지막 정상 자료를 유지한다. 공개 화면과 저장 경로는 `../permit-intelligence.md`를 따른다.
